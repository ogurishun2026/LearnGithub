## 二、四大核心原则

### 2.1 Think Before Coding（编码前思考）

**在写代码之前先思考** — 这是最容易被跳过的步骤。

具体做法：
- **明确假设**：在开始前陈述假设，不要假设用户总是对的
- **多角度解读**：对模糊需求提出多种可能的解释
- **敢于质疑**：当用户的方案有问题时勇于指出，而不是盲目执行
- **先理解再动手**：理解问题的本质而非表面指令

### 2.2 Simplicity First（简单性优先）

**代码不是越多越好** — 最小化代码，最小化复杂度。

核心要点：
- **拒绝投机**：不要添加"以后可能用到"的功能
- **200行原则**：能用200行解决的问题不要写1000行
- **保持精简**：只实现明确要求的功能，不做扩展
- **技术债意识**：理解过度工程的长期成本

### 2.3 Surgical Changes（精准修改）

**像外科手术一样精准** — 只改必须改的地方。

执行原则：
- **最小触碰**：只修改达成目标必需修改的代码
- **不美化邻接代码**：不要趁机"改善"周围的代码
- **定向修改**：改变是精确的、可控的
- **避免连锁反应**：理解每处修改的潜在影响

### 2.4 Goal-Driven Execution（目标驱动执行）

**把命令性任务转化为可验证的目标** — 明确你要达成的最终状态。

实践方法：
- **目标明确**：把"做什么"转化为"达到什么状态"
- **可验证性**：每个目标都应该能验证是否达成
- **结果导向**：关注输出而非过程
- **测试验证**：通过测试确认目标达成

## 三、安装方式

### 3.1 Claude Code Plugin（推荐）

通过 Claude Code 官方插件系统安装，自动加载。

### 3.2 CLAUDE.md 方式（项目级）

在项目根目录创建 `CLAUDE.md` 文件，将指南内容作为项目级指令。

这种方式的好处：
- **项目专属**：针对特定项目定制
- **团队共享**：团队成员统一遵循
- **版本控制**：可以随项目一起版本化
