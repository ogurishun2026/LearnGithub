## 一句话总结

这条视频展示的不是单个动作导出，而是一条“AI 生成动作数据 → 重定向到 Unreal 骨骼 → 训练 AnimGen 控制器 → 接入 Animation Blueprint”的动作系统流程。它的目标是让角色拥有可切换的个性化步态，并在行走、跑动、停止和转向之间获得更自然的过渡。

## 视频真正解决的问题

传统动作系统常见的问题是：动作资源少、步态僵硬、走跑停切换突兀、不同动作风格难以统一。视频的思路是把动作制作分成两层：

1. 用 Kimodo 生成一批风格一致但不必循环的动作样本。
2. 用 AnimGen 训练一个控制器，让角色根据速度、方向和状态连续输出动作。

这样做的重点不是“生成一条漂亮的动画”，而是构建一个可以持续响应输入的动作控制器。

## 完整流程

```text
动作风格目标
    ↓
Kimodo 文本 Prompt + 约束条件
    ↓
生成多个 3D 动作样本
    ↓
筛选、保存和整理动作数据集
    ↓
重定向到 Unreal / UEFN 目标骨骼
    ↓
准备行走、跑步、停止、转向等覆盖范围
    ↓
训练 AnimGen 控制器
    ↓
接入 Animation Blueprint
    ↓
用速度、方向和状态测试连续过渡
    ↓
清理脚步、根运动、朝向和特殊动作
```

## 视频流程

### 00:00-03:30：展示控制器与训练数据

作者先展示一个训练好的控制器。角色可以在行走、跑动和停止之间切换，并呈现特定的个性化步态风格。当前示例主要覆盖简单的走、停和少量转身，某些大幅度转向仍然不够顺滑。

视频还展示了训练数据库、动画蓝图和已经训练完成的控制器。动作样本由 Kimodo 生成，整体风格保持一致，而且多数样本是不循环的、带有真实人物不规则行走特征的动作。

### 03:30-05:00：准备 Kimodo 环境

作者使用云端 Windows GPU 虚拟机运行 Kimodo，提到 12 GB 显存配置和按小时计费方案。视频中还提到显卡资源有时需要在特定时间段抢占。整合包第一次使用先执行修复，修复后启动服务，等待网页界面出现即可操作。

这部分是运行环境经验，不是 AnimGen 的必要条件。视频没有给出完整的本地硬件最低要求，也没有证明视频中提到的云 GPU 价格长期有效。

### 05:00-08:30：用 Kimodo 生成动作

Kimodo 界面提供动作时长、随机种子或类似可复现参数、生成样本数量、姿势与轨迹约束、Prompt、生成和保存等控制项。

作者建议先用 Prompt 描述行走轨迹和动作风格，再通过约束条件控制动作不要偏离目标。视频建议使用语言模型帮助组织 Prompt，把轨迹、风格、接触要求和禁止项写清楚。

筛选动作时不能只看画面是否好看，还要检查脚底接触、根节点位移、身体前方向、左右骨骼和动作速度是否稳定。

### 08:30-09:40：保存和复用约束

作者展示了将约束配置保存下来。以后打开项目时，可以重新找到保存的约束并填入名称，避免每次从头配置。对于批量生产动作，约束配置应作为可复用资产管理。

### 09:40-10:50：训练并接入 AnimGen

视频展示了训练好的 AnimGen 控制器和 Animation Blueprint 节点。控制器根据运行时输入计算并输出连续动作。视频还提到，动作数据中没有手指动作时，需要在训练和动画蓝图设置中排除手指骨骼或相关输入。

### 10:50-11:57：训练速度与后续扩展

作者指出，更好的 GPU 会缩短训练时间，也可以使用更贵的显卡提高速度。视频最后表示会继续研究更复杂的动作系统和更多动作训练控制器。

## 角色动作制作的实用结论

- Kimodo 更适合生成同风格动作数据集，而不是只生成一条展示动画。
- AnimGen 的自然过渡依赖训练数据覆盖速度、方向、起步、减速、转向和停止。
- AI 生成动作中的脚滑、骨盆漂移、左右翻转和速度不一致，必须在训练前清理。
- 非 MetaHuman/UEFN 角色仍需要正确的骨架、重定向配置和比例检查。
- 训练控制器前应先验收 Idle、Forward Walk 和 Stop，再扩展 Run、Turn、Attack、Roll。
- 角色动作最终要在游戏内验证，而不能只看 Kimodo 或编辑器预览。

## 与已有动作流程的关系

此前的两条视频解决“如何从真人或 AI 视频得到可编辑动作”；本视频解决“如何把动作样本训练成可运行、可切换的动作系统”。三者可组合为：

```text
真人视频 / 豆包视频 / Kimodo 3D 动作
                    ↓
             动作解算或动作导出
                    ↓
           统一骨架与重定向清理
                    ↓
              Idle / Walk / Run / Stop
                    ↓
             AnimGen 控制器训练
                    ↓
              Animation Blueprint
```

## 局限

视频更接近思路梳理和操作演示，不是完整的从零训练教程。它没有完整解释训练数据格式、控制器输入输出定义、训练集划分、损失指标、失败重训和部署参数。“丝滑切换”也不是单个按钮效果，而是训练数据、骨架、根运动和运行时输入共同决定的结果。

## 推荐起步方案

1. 选定目标 Skeleton，先完成 Idle、Forward Walk 和 Stop 的重定向。
2. 用 Kimodo 生成 10-20 条同风格短动作样本。
3. 清理脚滑、左右翻转、速度不一致和姿态异常的样本。
4. 训练只覆盖走、停和小角度转向的最小控制器。
5. 在 Animation Blueprint 中接入速度、方向和加速度。
6. 在游戏内检查不同速度、反向移动、急停和转弯。
7. 通过视觉验收后，再扩展 Run、Attack 和 Roll。

## 最终判断

这套流程适合制作有独特风格的 NPC 步态、快速搭建第三人称移动原型，以及减少手工制作大量步态变体的成本。它不能替代骨架契约、动作清理、根运动检查和游戏内验收；正式项目应把 Kimodo 视为动作数据生成器，把 AnimGen 视为运行时动作控制器。
