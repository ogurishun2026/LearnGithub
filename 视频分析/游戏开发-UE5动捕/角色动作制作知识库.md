# UE5 / UEFN 角色动作制作知识库

## 目标

本知识库用于把真人视频、AI 生成视频和 AI 生成 3D 动作，转化为可重定向、可清理、可进入游戏运行时的角色动作系统。

核心原则是：

```text
动作来源 ≠ 最终动画
最终动画 ≠ 动作系统
动作系统 = 统一骨架 + 动作资产 + 清理验收 + 运行时控制器
```

## 三条视频形成的完整技术路线

| 阶段 | 可用方案 | 产出 | 主要风险 |
|------|----------|------|----------|
| 动作获取 | 真人视频 + UE5.8 MetaHuman Animator | 身体/面部捕捉结果 | 手部、面部、遮挡、设备要求 |
| 动作获取 | 豆包生成视频 + UE5.8 MetaHuman Animator | MetaHuman 动画初稿 | AI 视频漂移、脚滑、身体比例变化 |
| 动作生成 | Kimodo 文本 Prompt + 约束 | 3D 动作样本集 | 风格漂移、根运动不稳定、数据污染 |
| 资产整理 | Unreal 重定向、Control Rig、动画烘焙 | 目标骨架动画 | 骨骼映射、比例、朝向、根运动 |
| 系统运行 | AnimGen + Animation Blueprint | 走跑停转连续控制器 | 训练覆盖不足、输入定义不清、过渡不稳 |

## 推荐的项目落地顺序

### 阶段 1：建立骨架契约

在制作动作前，先锁定目标角色版本和骨架：

- `root -> pelvis` 保持直接层级。
- 明确身体前方向和参考姿势。
- 确认左右手脚、脊柱、颈部和头部命名。
- 确认目标 Skeleton、IK Rig 和 IK Retargeter 的版本路径。
- 不复用未经验证的旧 Skeleton。
- 自定义角色先单独做 Idle 和 Walk 重定向测试。

### 阶段 2：制作最小动作集

先制作可验收的最小集合：

1. Idle。
2. Forward Walk。
3. Stop。
4. Small Turn。
5. Run。

只有 Idle、Walk 和 Stop 的根运动、脚底和身体方向通过检查后，才扩展攻击、翻滚和受击。

### 阶段 3：选择动作来源

- 有演员和拍摄条件：优先真人视频捕捉，动作意图和接触关系更可控。
- 没有演员但需要快速原型：可用豆包生成符合动捕要求的视频，再进入 UE 解算。
- 需要大量统一风格步态：可用 Kimodo 生成 3D 动作样本，再训练 AnimGen。

不同来源可以进入同一条后处理链，但必须在统一骨架和参考姿势上汇合。

### 阶段 4：清理与重定向

每个动作进入训练或运行时前，至少检查：

- 根节点起止位移和旋转。
- 骨盆局部位移是否吞掉根运动。
- 行走方向是否与身体前方向一致。
- 左右手脚是否反转或交叉。
- 脚底是否滑动，膝盖是否穿插。
- 手掌、脚掌和道具接触是否可信。
- 动画时长、采样率和起止姿势是否适合拼接。

### 阶段 5：训练 AnimGen 控制器

训练数据应覆盖实际运行时空间：

- 速度：静止、慢走、正常走、跑步。
- 方向：前进、后退、左右和斜向。
- 状态：起步、持续移动、减速、停止。
- 转向：小角度、大角度、原地转身。
- 风格：每种风格都有足够的样本，而不是只改变一条动作。

如果数据集没有手指动作，就不要在控制器中假设存在可靠的手指输出；手指和武器动作可以作为独立层叠加。

## 动作数据的验收门槛

### 数值与结构检查

- 目标 Skeleton 和 IK 资产路径正确。
- 目标骨骼数量、父子关系和参考姿势没有异常。
- 根骨骼和骨盆缩放保持单位值。
- 目标动作时长为正，关键帧没有空段。
- 根运动和骨盆运动没有互相抵消。

### 视觉检查

- Persona 中 Reference Pose、Idle 和 Walk 均通过。
- 手臂、腿、脚、肘、手掌没有反向或交叉。
- 角色身体前方向与运动方向一致。
- 脚底接触稳定，没有明显漂移。
- 转向时身体不会突然翻转或横移。
- 重定向后服装、披风和身体没有明显穿插。

### 运行时检查

- 从 Idle 起步不会跳帧。
- Walk 到 Run 的速度变化连续。
- 减速和 Stop 不会滑步或突然锁死。
- 反向移动和斜向移动不会改变角色面向逻辑。
- 控制器切换风格时，姿态不会瞬间跳变。
- 攻击、翻滚等高优先级动作能正确打断或恢复移动。

## Kimodo 的项目使用规则

### Prompt 必须描述四件事

1. 动作语义：走、跑、急停、转身等。
2. 轨迹：直线、弧线、原地、向左或向右。
3. 风格：自信、谨慎、沉重、妖娆、机械等。
4. 约束：脚底接触、速度稳定、起止姿势、禁止跳跃或滑步。

### 生成样本的管理

- 固定角色和骨架。
- 保存 Prompt、随机种子、约束配置和生成时间。
- 每个动作保留预览和验收结果。
- 删除明显错误样本，不要依赖训练阶段自动修复。
- 用训练集、验证集和测试集分开检查控制器是否过拟合。

## UE 重定向规则

- Retarget Root 使用 `pelvis`。
- Source 和 Target 的 Root 链使用 `root -> root`。
- 根运动目标使用 `root`，骨盆单独处理。
- 每个版本使用隔离的目标 IK Rig 和 IK Retargeter。
- 不要用旧 Skeleton 或旧角色资产覆盖新角色。
- 先验证 Idle 和 Walk，再扩大动作集合。

## 常见失败与处理顺序

| 现象 | 优先检查 |
|------|----------|
| 角色不向前移动 | Root 链是否错误地经过 pelvis，根运动是否被抵消 |
| 角色面向反了 | 身体前方向、参考姿势和骨骼轴，不要只看 root 局部 X 轴 |
| 脚滑 | 源动作接触、根运动、目标腿长和重定向比例 |
| 手脚左右反转 | 骨骼命名、父子关系、IK 链和参考姿势 |
| 转向不顺 | 训练数据中的转向覆盖、速度/方向输入范围和转向动作数量 |
| 控制器输出僵硬 | 样本风格不一致、训练覆盖不足、数据中有错误动作 |
| 手指动作异常 | 训练数据没有手指轨迹或控制器误读了不存在的输出 |

排查时先确认源动作和骨骼，再检查重定向配置，最后才调整 AnimGen 和蓝图参数。不要用运行时参数掩盖错误的绑定或骨架。

## 当前知识库的结论

三条视频组合后，最稳妥的角色动作制作策略是：

```text
先用真实或 AI 来源获得动作
    ↓
统一到目标 Skeleton
    ↓
通过 Idle / Walk / Stop 验收
    ↓
整理成同风格动作数据集
    ↓
训练 AnimGen 控制器
    ↓
在 Animation Blueprint 与游戏内验证
```

Kimodo 负责提供动作数据，UE/MetaHuman Animator 负责从视频解算动作，重定向和 Control Rig 负责修正资产，AnimGen 负责把一批动作变成可响应输入的运行时系统。任何一个阶段的错误都会被后续阶段放大，所以“先验收资产，再训练控制器”是整个知识库的硬规则。
